# 微信、QQ、飞书消息渠道

APP 与独立网页输入服务复用消息连接器，处理平台消息后使用限定项目的输入身份提交给 Hub。两种输入端均可在设置中选择负责连接的在线输入端，用户可选择安装 APP 或运行网页输入服务。关闭窗口或浏览器后，由托盘服务保持连接。退出相应输入端服务后结束连接。

管理员在 **设置 → 消息渠道** 中选择负责连接的输入端、连接平台账号、选择 Hub 项目，并填写允许访问的用户。平台连接随所选输入端服务运行，适配器随 APP 和网页服务分发。

## 接入方式

| 平台 | 连接 | 凭据 | 当前消息支持 |
| --- | --- | --- | --- |
| 微信 | iLink 长轮询 | 在设置中用微信扫码 | 私聊文字收发；平台附带的语音识别文字作为文字处理 |
| QQ | 官方 Bot API v2 / Gateway WebSocket | App ID、App Secret | 单聊、群聊 @消息；平台附带的语音识别文字作为文字处理 |
| 飞书 | 官方 Go SDK 长连接 / Open API | 企业自建应用 App ID、App Secret | 私聊、群聊 @消息、话题隔离、文字及富文本输入、Markdown 富文本回复 |

当前不下载或上传图片、文件、原始语音或视频。纯附件消息会提示到 MewDex 中处理。进度文字和底层工具输出不逐条刷屏；最终文字回复与待处理请求会回到来源聊天。桌面中的原对话可继续查看完整过程。

## 微信

1. 选择执行设备和项目，勾选启用，保存设置。
2. 点击“生成微信登录二维码”，用微信扫码并确认。
3. 允许列表为空时，扫码账号的用户 ID 会自动加入。已有允许列表保留原值。
4. 向新连接的机器人发送文字。账号连接与渠道启用分别保存；给已关闭渠道扫码不会自动启用。

二维码只允许生成它的管理员输入身份轮询。区域服务地址仅接受可信的 `*.weixin.qq.com` HTTPS 地址；不会把登录凭据发往任意返回 URL。回复使用同一账号下该用户最近收到的 `context_token`。

## QQ

在 [QQ 开放平台](https://q.qq.com/) 创建机器人，开启 C2C、群聊 @消息权限。测试用户和群需要加入该应用的沙箱范围。将 App ID 与 App Secret 填入设置，选择项目后启用。网关只请求这两种消息共用的 intent，避免因额外频道权限未授权而拒绝连接。

先给机器人发一条消息，再从设置中的“最近收到的用户”复制平台 ID，加入允许用户并保存。群聊还必须把群 OpenID 加入允许群聊。只有允许的用户在允许的群 @机器人时才处理消息。

QQ 回复引用来源 `msg_id`，并保持稳定的 `msg_seq`，遵守平台被动回复的时效和数量限制。单条长回复最多发送四段，超长部分会明确提示到 MewDex 查看完整内容。连接断开后从已持久化的 session / sequence 恢复。平台可能拒绝超时、超量或含未配置 URL 的回复；原结果保存在 MewDex 中。发送 `/last` 可用新的入站消息重新获取当前会话最近一条回复。

## 飞书

在 [飞书开放平台](https://open.feishu.cn/) 创建企业自建应用：

1. 开启机器人能力，申请 `im:message:send_as_bot` 及接收单聊、群聊 @消息所需权限。
2. 在事件订阅中选择长连接方式，订阅 `im.message.receive_v1`。
3. 在 MewDex 填入 App ID、App Secret 并保存，使平台能够检测到长连接；发布应用到需要的可用范围。
4. 发消息后把自己的 `ou_…` Open ID 加入允许用户；群聊还需把 `oc_…` Chat ID 加入允许群聊。

机器人 Open ID 默认自动查询；可选填写用于核对。群聊必须提及机器人本身，提及其他用户或全体成员不会触发。话题 ID 纳入会话隔离，回复留在来源消息或话题中。

## 消息和会话

每个渠道绑定一个设备和项目。会话键包含平台、应用/微信账号、设备、项目、聊天类型、聊天 ID、话题 ID和用户 ID；同一群中的不同用户拥有各自的 MewDex 会话。更换目标设备、项目或平台账号不会复用原会话。

| 输入 | 行为 |
| --- | --- |
| 普通文字 | 首次创建会话；空闲时开始回合；忙碌或队列暂停时进入原队列 |
| `/help`、`/start` | 显示用法 |
| `/status` | 当前会话、设备、项目、状态和等待队列数 |
| `/last` | 获取当前会话最近 500 个事件内的最近一条完成回复；更早历史在 MewDex 中查看 |
| `/new` | 当前执行及队列状态处理完后，下条消息创建新会话 |
| `/stop` | 对当前会话提交停止请求；不声称后台进程已确认退出 |
| `/approve 请求编号` | 仅确认此会话当前权限范围内、具有有效执行范围的单次命令 |
| `/deny 请求编号` | 拒绝此会话中的普通待处理请求 |
| `/answer 请求编号 {"问题编号":["回答"]}` | 回答普通补充问题 |

完整文件差异、额外权限、表单和敏感问题在 MewDex 中处理。渠道身份是固定到所选项目的普通 `client`，不会取得管理员或模型出口权限。所有指令复用 Hub 原有入口，不直接操作执行引擎，也不接受外部路径或权限配置。空用户允许列表拒绝全部消息；群聊还要求允许聊天和 @机器人。

## 持久化与恢复

渠道配置、凭据、会话映射、入站消息、出站回复保存在所选输入端的私有渠道数据库中。Hub 保存普通输入身份、模型会话和指令回执。旧 Hub 渠道数据保留在原处，拆分部署后在选定输入端上重新配置。查询接口只返回“已配置”状态，不回显密钥；不向日志记录 SDK 的原始事件或凭据 URL。只向管理员开放设置与扫码接口。

入站消息先根据平台账号、聊天、用户和消息 ID 去重落库，再确认平台接收。每条消息在交给 Hub 前保存准确的指令；重启后只查询原回执，不重新选择开始或排队指令。结果不明时保留原指令编号并提示核实。

回传消息与读取事件游标在同一事务中保存。发送使用固定的微信 `client_id`、QQ `msg_id + msg_seq` 或飞书 `uuid`，失败最多重试八次；平台拒绝、超出窗口或最终送达不明仍可能导致回复未送达，不能把这些机制视为所有平台都保证恰好一次展示。

禁用、移除用户、更改项目或撤销输入身份后，未处理消息和回复重新检查当前授权。撤销的身份不会因服务重启自动重建；管理员显式保存渠道设置才能重新授权。修改允许列表和渠道开关即时生效。

## 参考与验证

设计参考 [Hermes Agent](https://github.com/NousResearch/hermes-agent/tree/f0d94882e89ab8d4098b5bb2f166adfb9ee0a0ab) 的统一消息适配、聊天会话和三个平台实现。参考清单和原始 MIT 许可见 [third_party/hermes-agent](../third_party/hermes-agent/README.md)。飞书使用 `github.com/larksuite/oapi-sdk-go/v3 v3.12.2`，二维码使用 `qrcode 1.5.4`。

2026-11-03 的本地模拟测试覆盖消息去重、重启原回执、忙碌排队、群聊用户隔离、撤销授权、管理员设置边界、微信 QR 身份归属及令牌/游标、QQ WebSocket 鉴权与恢复、飞书自身 @提及及原话题 Markdown 回复、UTF-8 分片和错误脱敏。平台凭据与真实账号尚未配置，真实微信/QQ/飞书收发验收须在配置后进行。
