# 架构约定

## 角色

MewDex 分为四个组件，平台 App 负责组合它们，运行角色由用户配置。

| 组件 | 代码归属 | 职责 |
| --- | --- | --- |
| Input Terminal（输入终端） | `apps/client/src/input-terminal/` | 用户输入、对话、结果与交互 |
| Execute Terminal（执行终端） | `internal/executor/`、`internal/engine/` | 本机执行与引擎会话 |
| Hub（管理终端） | `internal/hub/`、`internal/transport/` | 网络身份、设备注册、请求路由与事件 |
| Hub Controller（管理终端的管理器） | `apps/client/src/hub-controller/`、`internal/localnode/` | 本机管理与经过 Hub 授权的远程管理 |

Windows、macOS、桌面 Linux App 包含四个组件。Android、iOS / iPadOS App 包含 Input Terminal 和 Hub Controller。组件与平台组成以 `mewdex.product.json` 为准，平台外壳的能力声明嵌入这份清单。`apps/client/src/main.tsx` 组合界面与控制入口，Tauri 外壳按平台提供能力。桌面打开 App 时按配置启动本机 Hub 或 Execute Terminal，输入连接可指向本机或远程 Hub。

Hub Controller 通过本机原生接口管理服务配置、启停、自启动、数据与升级，通过 Hub API 管理远程设备、项目、授权和模型账号。移动端使用同一远程管理界面。各操作沿用当前身份与目标设备的权限。

组件名与协议身份分别建模。现有协议中的 `client` / `admin` 表示输入和管理身份，`executor` 表示节点身份，Hub Controller 使用已有的登录和授权接口。Gateway 属于 Hub 的可选模型网络出口能力。

执行节点具有独立设备身份。MewDex 账号作为中央登录身份，可在多个 Input Terminal 和 Hub Controller 使用。节点的 ChatGPT 账号提供该节点使用的模型订阅。

MewDex 账号、密码哈希及项目展示元数据保存在 Hub。输入终端没有已保存连接时，先匿名检查中央地址与协议，再读取服务器公开的认证方式及默认方式，最后才向已确认的服务器提交用户名密码或密钥。新建 Hub 时设置首个账号，账号密码为默认登录方式，同时可选密钥；已保存连接继续通过系统凭据库中的令牌恢复。已有数据尚无账号时，兼容管理员密钥或原配对码，登录后可设置用户名密码。没有匿名注册入口。无图形界面的 Hub 可用 `mewdex account -config <profile>` 从标准输入读取 `{username,password}` 完成首个账号配置，密码不放在命令参数中。

本项目按用户确认的可信个人网络运行：通过 MewDex 账号登录后，用户获得中央网络内全部执行节点和项目的管理权限，不再逐台申请输入权限。账号密码登录保持稳定的账号/输入身份编号，生成独立的随机登录令牌；原密钥在关联账号及修改密码后继续可用，访问管理可以撤销对应身份的登录令牌。旧版配对身份仍兼容原访问规则，执行节点的配对与出口授权独立保留。

项目创建通过 Hub 路由至目标执行节点，由节点确认并持久化真实目录绑定，再回传中央项目列表。名称与分类由 Hub 直接保存，可在节点离线时修改；修改、公开列表、事件和指令回执在同一事务内提交。重连及旧目录事件不能覆盖中央修改的名称与分类。项目路径与实际文件仍由执行节点负责，中央改名不会移动目录、改变已有对话的执行位置或同步项目文件。旧 Hub 没有 `central-projects` 能力时，输入端保留原在线编辑行为。

本机服务设置只管理该电脑的配置、启停、监听端口、自启动与数据维护，不提供项目清单或项目编辑入口。项目管理统一位于登录后的 Hub 工作台，目录选择与名称、分类修改复用 Hub 的授权与路由；已有节点目录绑定继续保留。

Input Terminal → Hub → Execute Terminal → Codex App Server（本机 stdio）。Execute Terminal 可独立选择 Hub 的 Gateway 能力作为模型网络出口。

远端执行器可以用 `engine.useHubGateway` 在回环地址启动临时 CONNECT 代理，再经配对 Hub 的 WebSocket 转发。公网使用 WSS，官方模型 TLS 保留在通道内。模型子进程只取得每次启动生成的本地代理密码，设备令牌留在 Go 服务中；Gateway 校验设备身份、出口授权和精确域名，撤销时关闭存量通道。独立 HTTPS CONNECT 出口仍可用于单独部署的 Gateway。

Hub 的 `gateway.forwardDeviceId` 可指定已配对的远端 Gateway 节点作为模型出口。该节点通过现有控制连接接收转发请求，再主动建立一次性 WSS 数据连接，所有连接共用 Hub 的 HTTPS 入口。Gateway 可以单独运行，配置 `hub: false`、`executor: false`、`hubUrl`、`nodeTokenFile` 和 `gateway.allowedHosts` 即可。出口机器已有本地 HTTP 代理时，可通过 `gateway.upstreamProxyUrl` 接入。Hub 检查调用节点的出口权限，数据连接绑定指定出口节点的身份和控制连接，指定节点离线时返回失败。各执行器继续使用自己的模型账号及项目目录。

首版为一个活动 Hub、多输入端、多执行端。Hub 为可达的自托管地址；局域网/私有网络及 TLS 反向代理均可接入。不构建多主选举或 NAT 穿透服务。

## 模块边界

- `internal/protocol`：版本化的设备、项目、会话、命令和事件协议。
- `internal/store`：SQLite 状态与迁移，业务通过接口访问。
- `internal/engine`：引擎接口与 Codex JSON-RPC 适配，不依赖界面和 Hub。
- `internal/executionscope`：由本机可信路径生成命名执行权限、绑定范围指纹并核对引擎响应，覆盖完整会话生命周期。
- `internal/attachments`：附件的不可变归属、完整性校验与按会话隔离的只读视图，独立于输入界面。
- `internal/projectfiles`：在本机项目根目录内读取目录和普通文件，复用执行范围的私有路径边界，不跟随符号链接或 Windows 重解析链接；不依赖模型、Hub 或界面。
- `internal/childprocess`：引擎进程的启动、等待、平台进程范围与输出限制，不依赖模型 RPC。
- `internal/processidentity`：Mac 内核进程出生身份、不可变父子关系和带版本核对的信号接口，不读取命令参数、环境或模型凭据。
- `internal/serviceguard`：OS 管理与直接服务入口共用的数据租约边界。Mac 在独立会话中保留监护进程，执行前交接身份，清理结束后释放继承的安装与数据租约；监护丢失或出生链无法确认时保留未核实标记。
- `internal/lifecycle` 与 `localnode` 的恢复记录：保留系统启动批次，核对租约、设备配置和原冻结标记，通过本机面板保存与采用恢复记录；回复丢失后按原记录读回。解除启动限制前，`store` 原子保存旧执行身份的快照；`executor` 提供独立的结束旧执行操作，释放项目占用、保留原始输入与未知结果，旧会话只读。手机和未来输入端只引用公开恢复编号，不接触 OS 证明。真实重启与本机恢复面板的原生实操仍待完成。
- `internal/startup`：按安装隔离的系统启动登记、所有权核对、结果观察和平台适配；不保存模型凭据。
- `internal/hubproxy`：Hub 进程内的可选 SSH 反向代理，保存独立设置、核对服务器主机密钥、重连并随 Hub 退出清理。
- `internal/hubtray`：Windows Hub 自身的托盘入口，调用与桌面端相同的本机服务管理接口；不派生托盘或 SSH 常驻进程。
- `internal/executor`：本机执行、工作区约束、指令去重与任务控制。
- `internal/hub`：设备注册、访问控制、路由、事件投递与查询 API。
- `internal/transport`：节点连接、重连和事件补传。
- `internal/gateway`：受限目标的网络转发，独立于会话管理。
- `internal/localnode`：本机设备配置、服务生命周期、项目配置、备份恢复、当前安装升级和执行端重新配对；不依赖图形界面。
- `internal/runtimefiles`：按内容哈希保存服务程序和完整引擎资源，避免后台运行程序锁住安装目录。
- `internal/workspace`：目录规范化、符号链接解析及工作区重叠判断。
- `internal/backup`：流式加密归档、路径与清单校验、向新目录解包及校验复制；业务选择与配置采用留在本机管理层。
- `packages/sdk`：独立 TypeScript SDK，不引用 React、Tauri 或浏览器存储。
- `apps/client`：平台 App 组合层，分别装配 `src/input-terminal` 和 `src/hub-controller`。平台存储与通知通过适配器注入。

当前优先完善 Windows 桌面工作台，交互组件仍可由其他输入形态复用。设备选择、对话导航、快速切换、消息阅读和设置框架按职责拆分；草稿按执行设备与对话归属，发送回执只清除对应的已发送内容。Markdown 渲染使用 `react-markdown` 与 GFM 插件，代码块与消息复用复制组件；网络 SDK 不承担呈现或本机存储职责。Windows 窗口几何状态交给固定的 Tauri window-state 插件，不保存隐藏状态。界面层级与快捷键见 [桌面体验](desktop-experience.md)。

`workspaceNavigation` 共用对话的设备/项目上下文、关键词匹配及快速切换分组，只处理已授权快照的投影。快速切换、侧栏和归档页不各自拼装搜索规则；项目入口、输入区选择器与继续草稿调用同一导航方法，切换草稿归属但不创建或执行会话。快速切换以目标编号保留选择，与会话更新后的排序位置分离。

设备选择器与快速切换复用 `orderedDevices`、`deviceMatches`、`deviceDescription` 及 `DeviceIcon`，默认网络导航也使用同一排序；有效的现有选择不随状态或排序改变。`useKeyboardList` 只管理界面的高亮编号、滚动定位、方向键与明确选择事件，不持有设备访问范围或执行操作；两个弹窗分别保留原有打开、关闭和输入聚焦入口。

`executionTarget` 从当前可见设备及原项目编号投影编辑、执行条件与缺失原因，输入区、发送、附件投递和空白页共用。既有对话项目不使用首个项目回退，设备在线与网络连接仍由原发送条件处理；此投影不替代 Hub 的授权或执行端的项目检查。`ConversationWelcome` 只呈现目标与手动设置入口，添加执行设备进入既有配对分类，不主动邀请或更改设备配置。

`composerSubmission` 从当前会话投影普通发送的 `start`/`steer` 意图及排队说明，工作台发送路径与主按钮使用同一结果，停止中或未知状态不回退为新启动。明确排队继续使用原 `enqueue`；不会因主发送暂停而自动排队。`ConversationComposer` 只接收编辑、文件与操作回调及项目/附件呈现位置，复用原 DOM 编辑位置与输入偏好；草稿持久化、异步创建归属、回执、历史和 SDK 仍由既有控制器管理。

`useOutputReading` 按对话与历史游标保留窗口内的输出阅读选择，终端再按命令编号区分查找与视口，差异保留文件及呈现设置。它只保存编号、查找文字和位置，不保存命令输出或增加查询。`useConversationHistory` 提供稳定的阅读上下文及恢复状态，输出定位只作用于原上下文的新用户动作；恢复查找不自动聚焦。缺失命令或差异文件保持明确空状态，由用户选择当前记录；配对退出与私有范围清除同时释放阅读缓存。

`useDialogReturnFocus` 补齐没有 `Dialog.Trigger` 的受控弹窗关闭行为，打开前记录原控件及外层入口；弹窗间交接通过弱映射保留外层入口，嵌套关闭优先回到仍存在的原控件。关闭时释放记录，保留已经明确取得焦点的新位置，主动导航可显式跳过返回。`SettingsFrame` 与各独立窗口复用此行为；上下文菜单重命名继续使用明确的原列表项，顶部重命名传递自己的选项按钮。该处理不登记全局系统快捷键或替代原生按键诊断。

侧栏整理使用固定 `@radix-ui/react-context-menu 2.4.1`，沿用同一组件体系的菜单定位、键盘与焦点管理，参考 [官方 Context Menu 文档](https://www.radix-ui.com/primitives/docs/components/context-menu)。`sessionManagementActions` 共用管理选项，侧栏与顶部菜单继续调用原会话更新和重命名方法，不选择或执行目标会话；错误留在对应侧栏项，视图退出后释放。菜单占用焦点时暂停全局工作台快捷键，重命名保留原触发项用于返回。

`projectFileLocation` 分离文件路径与引用起始行，文件查看器继续只向原接口传递路径，行号随本次快照预览保留。普通附件与项目快照共用 `TextFilePreview` 和既有查找栏；`textPreview` 只对前 256 KiB 的已读字节解码，按 BOM 或用户选择处理编码，完整文件保存继续使用原 Blob。显示设置不进入 SDK、Hub 或模型指令。

`ComposerActivity` 独立管理输入端暂存的发送中状态和错误提示，以原设备/对话或新对话项目草稿为键。同一草稿同步去重，不同草稿可分别等待回执；创建成功时与文字及上传归属一同转移到新会话，异步完成只释放原操作。`useComposerActivity` 连接 React 订阅，访问范围清除后旧反馈不再回填。它不路由网络、不改变项目执行并发限制，也不替代 Hub 的持久回执和未知结果处理。

本次输入的本机待确认记录额外保留原草稿键，完成或显式关闭提示时通过 `completeComposerDraft` 只移除已提交的文字与附件；等待期间新改的文字及新增附件保留。界面切到其他对话后仍处理原草稿，不清理当前输入。仅有 Hub 元数据的恢复记录没有本机内容快照，不能据此猜测并清除草稿。创建回执恢复时，本机已知的原草稿可转入新会话，但只有用户仍在原选择位置时才导航过去。

`commandRecovery.ts` 保存输入端暂存类型与可见元数据投影，供恢复 hook、摘要、回执卡和二级窗口共用，不再由业务 hook 导入 UI 组件类型。分组与标签只引用当前可见设备和会话，不把原输入作为标题；原会话必须属于相同执行设备才提供导航。发送、停止与队列取消共用结果分类，已经进入原编号待确认流程的操作不重复生成带技术编号的主区错误。窗口复用同一份恢复查询及分页，不新建回执状态或轮询循环；访问范围清除时关闭窗口，旧范围的异步回执不再处理草稿。

输入端的 `useWorkspaceView` 独立保存网络与身份范围内的工作位置、每设备项目及布局偏好。网络同步在首次授权快照进入后调用一次恢复入口，之后重连继续保留当前选择；视图模块不发起执行指令。分栏拖动组件只处理布局和最终比例提交，文本框自动高度由通用 hook 处理，不进入网络 SDK。输入提示和工作位置共用网络/输入身份范围标识，凭据不进入存储键。

`useComposerPosition` 仅在窗口内按既有草稿键记录输入框的选区和滚动数字，使用选择/滚动/失焦事件及工作区选择订阅在旧 DOM 更新前采集。恢复排在自动高度处理之后，不主动聚焦；显式聚焦仍由原入口调度。新对话归属迁移与草稿清除通过原共用方法同步处理，不改变持久文字、输入法事件、发送或网络协议。

`useConversationHistory` 统一实时视图、双向历史页与搜索定位，复用有界事件窗口。搜索由 Hub 从当前授权对话的持久用户文本和完整模型消息生成结果，不依赖执行端在线或模型 RPC，也不额外复制一份对话数据库。重复完成记录按消息编号取最新内容；分页先选定最新记录再应用序号游标。片段按 Unicode 字符截取，返回独立的匹配文字段，界面不把结果片段当 HTML。

任务计划同样复用持久事件：执行器原有的 `turn/plan/updated` 通知继续正常保存，`store.TaskPlan` 用会话/设备/序号与部分索引读取步骤，再关联同一历史位置的回合开始或结束。没有新增计划状态表，也不把展示计划变为执行队列。新回合不继承旧计划，回合结束不替引擎完成步骤；空计划清空显示。Hub 通过输入端的当前项目授权返回公开投影，SDK 提供独立读取与取消。

`useTaskPlan` 将实时位置和历史页末尾映射为同一个独占游标接口。选中流中的计划与回合事件只失效实时查询，重连失效当前计划缓存；有界消息窗口不决定计划是否仍可见。`taskPlanPresentation` 独立处理数量、当前步骤和历史/离线/暂停/待核实文案，折叠组件只负责呈现，不修改会话或执行状态。Hub 快照的可选能力声明避免新界面向旧 Hub 发起不支持的读取，手机和未来网页可复用协议而无需本机执行能力。

共享 SDK 只提供搜索和正反向历史读取；查询取消、结果列表及原消息的聚焦与滚动留在输入端。搜索弹窗按提交读取，关闭后取消请求并释放结果缓存，关键词仅由当前对话的工作台内存记忆。历史页的未完整回复明确标为片段，完整消息事件继续替换之前的增量文字；历史浏览不改写草稿或执行状态。

回复未读复用同一条输入同步流。Hub 从持久事件的完整模型文字生成每对话最新回复序号，通过快照补齐离线期间的更新；后台对话仅投影 `conversation.changed`，不发送正文。回复专用的部分索引承接快照查询，不新增另一份消息或任务状态表。先按当前身份校验事件与可见会话，再返回位置提示。

`ConversationReadLedger` 只处理回复序号、当前输入的阅读位置和存储适配，不依赖 React、DOM 或执行器；`useConversationReads` 连接同步回调与界面。阅读区在前台、未被对话框遮住并到达最新内容时，按已经呈现的事件序号确认已读。阅读位置按网络/输入身份留在本机，与系统提醒开关独立；首份支持快照建立旧历史基线，重连与重开继续比较持久位置。手机或未来网页输入端可以复用同一状态模块，不需要本机服务能力。

输入端的 `outputs.ts` 按引擎 item ID 投影命令输出，区分增量正文与完整 `aggregatedOutput`，并保留命令状态、目录、退出码和耗时。投影按会话隔离，不通过查看输出调用模型或执行命令。终端继续使用固定的 xterm 5.5.0，查找采用相应版本的 [官方搜索扩展 0.15.0](https://github.com/xtermjs/xterm.js/tree/5.5.0/addons/addon-search)，在当前缓冲区中查询；平台 SDK 不承担这些呈现职责。

`unifiedDiff.ts` 独立解析统一差异，计算旧/新行号和增删数量，解码 Git 引号及 UTF-8 八进制文件名，同时保留原始字节序列供复制。差异组件只负责文件选择、排版、匹配行定位和将当前文件引用交给已有查看器。显示层不创建本机文件路径授权，也不应用差异。相同回合的差异未变时复用呈现结果，流式对话更新不重新解析全部差异。

网络任务概览由 Hub 组合已授权会话与数据库活动计数；请求和队列使用状态/会话索引，避免把历史输入正文全部载入应用。公开协议只返回计数及现有会话视图，独立 SDK 提供查询，界面通过同一个 hook 更新导航数量和任务列表。选中流对其他对话的请求/队列变更只发送 `activity.changed` 刷新提示，当前对话和独立提醒订阅继续接收各自需要的原有投影。

附件元数据和正文共用 SDK 的认证响应入口，JSON 与二进制消费分开。历史消息保留文本与附件引用的区分，草稿和历史共用文件卡片，只有用户打开预览或保存时才读取正文。桌面保存桥接只接收二进制和文件名，通过系统保存对话框选择目标，网络凭据不进入本机命令；原始二进制 IPC 避免把文件展开成 JSON 数字数组。当前交互读取由会话级 hook 提供，待处理提示、对话状态和表单共用同一份查询；问答字段独立复用，未知回复按原指令编号读取结果。

`InteractionResponses` 管理当前输入窗口的表单值及回复状态，通过注入的 SDK 发送/回执方法工作，不依赖 React、DOM、平台或持久存储。状态按执行设备、会话和请求绑定，同步锁定提交，切换页面不销毁原答复状态。明确失败保留输入供修改，已提交和未知结果清除答案；未知状态只能读取原编号，不能再次回复。卡片与待确认操作窗口共用终态应用逻辑，迟到的旧观察不能覆盖已经确认的结果。

`questionValues` 共用字段值类型及数字字段识别，编辑值与正式回复的数值分开。接受表单时，状态层转换数字、核对对应约束并投影字段错误，其他文字保持原样；可选数字空白省略，拒绝不附带填写值。字段错误与原请求一起留在本次窗口内，视图只负责标记、辅助说明和定位；执行端仍执行原最终校验，SDK 与协议没有新增展示状态。

`useInteractionResponses` 将输入窗口级状态接入原会话请求查询；完成后仅使原会话查询失效，避免 React 查询观察器切换后刷新到别的对话。成功读取的待处理列表清理已结束请求的内存值，访问范围重置清空状态并撤销旧异步写入，不恢复或发送任何答案。`InteractionPanel` 只处理当前会话的可用条件、字段与按钮呈现，问题值类型来自共享模块；不会因为卡片重新挂载重新发送、重建未知结果或丢失未提交填写。

`useInteractionFocus` 共用会话内入口和网络任务入口的显式定位意图，复用工作位置的设备/会话/选择版本。先返回最新视图，待对应查询完成再聚焦中立的请求区域；历史模式或用户选择变化会取消旧意图，请求已经结束则不保留定位等待。新请求到达不会主动移动焦点。历史页不渲染实时请求表单；切换历史产生的卸载与回复暂存分开，因此不丢失填写和未知回执，也不把当前授权动作混入旧回合上下文。

项目文件使用独立的 `file.list` 与 `file.export` 指令，不经过模型 RPC。执行器从当前可信项目配置建立只读文件范围，旧执行的范围和占用记录保持不变。显式回传先在执行端保存不可变附件副本，再以本地发布器或认证 HTTP 流送至 Hub；Hub 用原输入指令固定归属、设备与项目，验证字节后将副本索引与 `file.exported` 事件在一个事务中保存。存储回执不可靠时保留原编号供查询，不自动再读一遍源文件。列表由 SDK 查询，Windows、手机和未来网页可复用，同一份副本继续使用现有附件授权、预览和保存能力。

设备以 `capabilities` 声明是否支持项目文件操作。消息中的路径只导航至文件查看器，用户主动读取后才回传。Windows 的目录定位单独通过原生桥接引用已配置的设备和项目编号；Go 返回可信本机路径，Rust 调用系统定位，不接受网络或 Markdown 提供的任意本机路径。该桌面适配不进入网络 SDK。

原生输入凭据由不依赖 Tauri 的 `credential_store.rs` 处理：Windows Credential Manager、Mac Keychain、iOS 设备解锁策略、Android Keystore 和 Linux Secret Service 共用同一连接格式。Tauri 桥接只负责在后台线程调用，系统凭据库等待不会阻塞窗口；缺少可用系统服务时返回明确错误。Linux 适配采用固定的 [Secret Service 凭据库](https://docs.rs/zbus-secret-service-keyring-store/1.0.1/zbus_secret_service_keyring_store/)，独立于服务器执行身份的配置文件。

模型账号由执行设备管理，独立 SDK 封装现有状态读取、设备码登录及取消指令。`useModelAccount` 为当前设备提示和设置页共用缓存与本次登录状态，查询不刷新模型凭据，不自动发起登录。已登录时主对话区保留任务内容；需要配置时才提供当前设备的设置入口。普通输入身份不读取管理账号状态。只读 `account.read` 的回执继续保存，但不进入需要人工跟进的操作恢复列表，避免背景状态查询占据输入区或阻塞任务。

模型目录通过独立的 `model.list` 读取指令沿用现有 Hub 路由、项目授权与回执。执行器调用固定引擎的 `model/list`，只投影公开模型、强度和说明，保留分页游标；不创建或加载模型对话。目录只读回执仍可查询，但不进入人工操作恢复。设备分别声明 `model-catalog` 与 `reasoning-policy`，共享输入端据此展示能力。

`ModelSettings` 承担二级模型选择界面，`modelSelection.ts` 处理名称解析和切换后的强度选择；模型目录的推荐项不用于猜测继承配置。推理强度是随策略保存的可选字符串，与固定引擎 schema 一致，未知的新取值继续来自执行端目录。每回合通过现有 `collaborationMode.settings.reasoning_effort` 显式发送选择，未覆盖时为 `null`。版本、历史恢复、队列和多输入并发继续使用原策略流程，不改写全局引擎配置。模型目录的用途与强度字段以 [官方 App Server 文档](https://learn.chatgpt.com/docs/app-server#models) 及项目内 0.162.1 schema 为依据，目录不被当作账号权限证明。

`Policy.collaborationMode` 单独表示协作方式，与验证范围 `Policy.mode` 分开。空值为直接工作，`plan` 为方案讨论；显式 `default` 在规范化后回到空值。空字段不序列化，默认策略的既有指令和版本指纹保持；方案模式将讨论约束包含在同一份版本化任务指令中。执行器按原策略快照在 `turn/start.collaborationMode.mode` 发送 `default/plan`，模型、强度、项目范围、人工审批和历史均沿用既有流程。

[官方 App Server 文档](https://learn.chatgpt.com/docs/app-server) 说明 `settings.developer_instructions=null` 使用所选模式的内置指令。MewDex 继续显式发送自己的历史指令，因此方案约束也由任务策略生成并保存，不依赖空值再注入内置文本；这不是只读沙箱声明。模式枚举以本项目固定 0.162.1 schema 为准，具体模型提供哪些提问工具仍需真实引擎流程确认，不由模式名称推断。

Hub 和执行端分别声明 `collaboration-modes`；输入端取两端能力的交集。Hub 必须理解并保留新增策略字段，不能只根据执行端能力放开 UI。旧执行端忽略未知字段，因此 Hub 对显式或继承的方案讨论、方案版本恢复会在派发前记录明确失败，不把它转成直接工作；原编号重试继续返回原结果。停止、核实和其他控制操作不被此能力条件阻止。SDK、队列和历史都复用原策略对象，没有新增独立模式状态表或系统配置。

工作台提醒默认关闭，开启后使用独立的事件订阅；当前对话继续采用选中正文流和有界历史窗口。分类、游标和语义去重复用于各形态输入端，系统权限、投递和窗口唤起留在平台适配器。原生端恢复前台时读取当前系统权限，投递调用等待原生命令结果；权限申请由用户明确触发。当前实现覆盖在线系统提醒和返回应用后的补齐，后台远程推送仍需独立基础设施，不作为已交付能力。

通知点击在原生初始化时登记，并以单条定位提示跨过输入窗口启动和短时挂起；共享输入端订阅后消费，退出后的在途响应失效。固定通知库 `2.8.0` 的 iOS 回调原先遗漏 `extra`，并强制使用当前进程的内存记录；Android 初始 Intent 也可能早于首个监听器。项目内保留最小修补及原始许可证，来源与差异见 [通知库修补记录](../third_party/tauri-plugin-notification/MEWDEX-PATCHES.md)。这些修补不替代后续实际 OS 投递与点击联调。该依赖放在 `third_party`，避免触发 Go 对根目录 `vendor` 的自动依赖模式。

输入端的 `AttachmentUploads` 独立管理暂存文件、两个并行传输位置和逐项状态，不依赖 React、DOM 或本机服务。文件选择时捕获设备、项目和草稿；回传结果核对原目标后，按选择顺序调用草稿的定向追加入口。不同草稿独立完成，单个失败不停止其他传输；只有原草稿的未处理项阻止它发送。`useAttachmentUploads` 通过订阅接入视图，SDK 只接收文件名、设备/项目及 AbortSignal，不序列化输入端草稿键。

新对话建立或恢复创建回执时，草稿和上传归属通过同一入口移动，保持已经发起的文件传输。取消与清除先移除本次任务所有权，再终止请求，因此迟到响应不能重新加入草稿。身份或授权变化及输入组件释放复用该清除入口；未完成文件不保存到本机存储，已加入草稿的附件引用仍由原模块持久化。共享输入组件可复用这套行为，原生选择、拖入和剪贴板只负责提供 File。

`composerDrafts.ts` 共用草稿键、数据类型、原目标解析与列表投影。投影合并本机保存的文字/附件引用和暂存上传状态，保持完整原文，界面只展示简短预览；搜索仅在本机当前输入范围内进行。目标解析从当前可见设备与会话取得名称和项目，不用目录默认项代替原位置。设置中的草稿页复用该投影；继续编辑仅调用原导航入口，临时不可用的目标保留内容和复制入口，不创建或恢复执行。

## 会话与控制

会话绑定设备 ID、项目目录、引擎会话 ID、策略版本。输入端可跨设备继续会话，执行位置保持不变。跨设备迁移明确处理文件和环境。

命令使用客户端生成的唯一 ID，服务端持久登记。结果不明的执行命令不能自动重放。执行端事件先持久化，再发送并确认，Hub 去重并分配全局递增序号。输入端按序号补齐事件。

停止请求优先于普通指令。回合中断与任务进程停止分别报告。停止冻结队列，继续由用户显式触发；停止不回滚文件。失联不等于已停止。

项目 ID 与真实目录的绑定持久保存，移除项目后也不能把同一 ID 指向另一目录。同一执行器内，运行中或结果未知的对话独占该目录及其父子目录；不同名称、项目 ID 或符号链接不能绕过。当前不是跨进程或共享文件系统的分布式锁。

模型回合结束后继续查询引擎登记的后台进程。构建等进程尚在运行时保留工作区占用，后续排队输入继续等待；列表不可读取时暂停并冻结。只有确认这些进程已退出后才释放目录和推进队列。该证据范围仍是引擎登记的进程，操作系统孤立进程的完整清理另行实现和验证。

## 桌面本机服务与输入界面

桌面应用同时提供输入工作台和本机设备管理入口。Rust 只调用固定的 Go 程序、选择目录与访问平台凭据库；配置、执行、转发和生命周期逻辑都在可复用的 Go 模块中。关闭窗口后后台服务继续运行，启动与停止以设备和实例标识确认，不按缓存 PID 强杀。

Windows 首次使用与后续服务管理共用 `useLocalDevice` 操作控制器。创建、启动和输入连接按一次用户动作顺序调用原本机接口；重新保存输入凭据时复用已经获得的输入身份。本机面板自动读取状态，以分类页面组织服务、启动、数据和维护，切换分类保留后台任务视图。项目管理通过登录后的 Hub 工作台进入。读取到没有后台操作后停止空闲轮询；待确认或进行中的操作仍按原编号查询。

`LocalServiceActions` 共用概览和执行端配对页的启动、停止及输入连接入口，继续使用 `useLocalDevice` 的原生命周期操作；未接入新重试、配对或服务控制协议。恢复结果根据原恢复方案的角色说明启动顺序，后续定位依当前本机快照进入连接或概览。页面导航不自动连接、生成配对码、修改账号或解冻队列。

本机管理默认使用应用数据目录，也可通过原生选择器接入已有 `device.json` 所在目录。Rust 只保存目录选择，读取及预览仍交给固定 Go 管理程序；采用前再次读取设备身份，变化时返回重新选择。输入页面仅持有临时预览编号，不能通过请求指定任意服务根目录。采用后重新建立本机管理视图，后续设备操作统一读取已保存位置；原配置、运行实例、账号与数据不迁移。开发环境显式指定目录时优先保持该隔离范围，切换入口不可用。这个本机适配不进入网络 SDK，手机和未来网页不需要具备它。

`useInputConnection` 独立处理输入身份恢复、明确保存与移除；`connectionRead` 为它和网络快照同步提供读取超时及重试分类，网络请求使用 SDK 的 AbortSignal。重试只读原身份或快照，不创建配对、发送消息或重放未知操作。明确授权失败和其他需处理的配置错误不会进入自动读取循环；HTTP 错误保留状态码，包括反向代理返回纯文本的情况。工作台用同步连接状态控制消息发送，并把缓存设备状态标为上次状态。

当保存的输入地址与本机 Hub 地址匹配时，连接恢复视图复用 `useLocalDevice` 的启动操作，成功后重新读取原输入身份；不调用会创建新管理员身份的 `connect`。本机地址由 Go 管理层统一生成，包括停止状态。Windows 已实际通过这一入口启动独立后台实例，在图形输入关闭与重编译期间保持运行；当前仍使用项目内配置，系统登录触发及正式安装迁移另行联调。

Go 服务、Codex 及其配套资源随桌面软件准备；运行前校验清单，并保存到应用自己的版本目录，不要求另装全局 CLI。首次配置默认使用独立的模型目录。输入身份与执行身份分别保存；手机和未来网页端只使用网络 SDK，不需要本机服务接口或模型凭据。

共享输入 UI 的 `inputViewport.ts` 处理触控编辑、键盘可见区域和消息区尺寸变化，SDK 保持不依赖 DOM。输入聚焦时按可见区域放置工作台，阅读区原本接近底部时保持最新回复可见。可见区域的语义参考 [VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport)；目标设备的实际布局仍由原生运行检查确认。

本机入口可以创建 Hub、加入已有网络、启用本机执行及选择项目。首次 Hub 只监听回环地址，其他设备连接需要另行配置可访问的 HTTPS 入口。当前原生桥接及开发构建不等同于自启动、升级迁移、备份恢复或签名安装器交付。

自动启动登记已接入本机面板：Windows 任务计划程序和 Mac LaunchAgent 使用用户登录会话；Linux root 使用系统 systemd 服务，非 root 使用用户服务。登记指向按内容哈希保存的服务程序，前台入口持有完整安装租约。入口绑定设备配置指纹，恢复或修改配置后不自动采用新状态。关闭自动启动保留当前运行的服务，显式停止不恢复任务队列。当前三平台证据为隔离安装目录中的登记、启动、停止与注销，不包括真实开机、注销登录或签名安装器。

## 身份和数据

区分输入端身份、执行端身份和模型认证。设备使用一次性配对，长期凭据不进入 URL 和日志。浏览器 WebSocket 使用短时一次性票据。公网连接要求 TLS，明文仅用于回环或明确的私有开发环境。

模型凭据留在官方支持的本地认证路径；不转发到输入端。项目仅在配置允许的根目录内执行。执行范围与网络身份授权相互独立。

项目目录绑定与重叠锁负责调度，操作系统沙箱负责读写和网络边界。新建、恢复和基础指令分叉选择并核对命名配置；每回合复查本机范围指纹，并沿用已核对的活动配置。不能在 `turn/start` 重新选择只存在于该对话覆盖层中的配置名称，因为引擎可能从进程配置重载并丢失其定义。缺失配置回执不创建可用对话。原始账号/数据路径、命令环境限制和 Windows 沙箱实现进入范围指纹；变化后不能沿用旧编号。

Windows 源码选择固定引擎 0.162.1 的 MXC，并显式禁止静默回退到旧沙箱。已授权的 0.154.0 elevated 准备已完成，但实际工具只能证明私有路径禁止读取，未守住完整的目录读取白名单；因此不以该准备成功替代隔离实现。独立 MXC 命令已证明工作目录可读、目录外标记不可读，正式执行器的新版适配仍在继续。MXC 不支持的设备须显示不可用原因，不能隐式放宽权限。

模型可读的会话附件视图须与私有数据目录分开；固定版本 Linux 沙箱不能在禁止的父目录内重新开放只读子目录。只有本机管理层可提供运行资源和数据路径，输入协议只传附件编号，不接受任意路径或权限配置表。数据与运行资源的具体布局必须在接入正式执行器前核对，避免将整个安装目录授予读取权限。

引擎提供其实际启动程序与账号目录；有资源清单时只授权校验通过的文件，独立原生程序仅授权程序自身，缺少伴随文件时失败，不扩大到整个目录。配置位于项目内时，其所在目录也作为私有目录保护，避免相邻输入凭据被项目读取权限覆盖。`mewdex-inputs-*` 为按设备、项目和数据位置绑定的派生附件目录，不存模型或网络身份。

命令环境使用固定允许列表，过滤低层配置恢复的令牌、代理密码和登录 shell 环境。补充问题和支持的表单继续通过输入端回答。命令只支持本次确认，且必须有能阻止引擎绕过沙箱的私有路径禁止规则；额外权限只支持具体文件路径及本回合网络开关，接收请求和提交回复前均核对范围。不能通过回复夹带路径或永久授权。私有身份、数据目录及只读运行资源不能被扩权覆盖。

文件审批使用原生文件变更事件，按对话、回合和内部工具编号保存有界预览，因此也能处理新版工具编排产生的内部调用。确认前再次核对相同变更，缺少预览或要求持续开放目录时不能接受；回合结束、停止或服务重启使旧预览失效。Hub 只允许管理员输入端接受额外权限，普通输入端仍可处理当前范围内的单次命令、文件确认和问题。手机可持有管理员输入身份，仍不承担本机执行角色。

Windows 正式执行器已完成目录外读取拒绝、本回合授权及失效、原对话恢复和基础指令分叉，以及文件确认后私有写入失败的开发检查；命令确认没有放开未授权网络。Mac 和 Linux 已用新固定版完成临时读取与网络授权失效、恢复与分叉、文件确认仍保留私有禁止，以及环境隔离检查。请求由确定性的回环响应提供器产生，没有官方推理或账号授权。

Hub 保存索引与事件，Executor 保存本机运行状态，Codex 保存引擎历史。附件、终端日志和数据库分别存储。项目文档留在项目；内部 `.state` 为忽略的开发运行状态。

设备恢复和升级共用最终的核对与原子配置切换。恢复使旧网络授权失效；升级只从当前停止状态复制，保留当前授权和模型目录，冻结任务并重新绑定执行范围。历史附件通过已送达输入证据在会话只读视图重建当前路径，不直接读取旧路径。实际回合指令与用户策略分别保存。数据范围、证据及尚待检查的界面流程见 [设备数据生命周期](data-lifecycle.md)。
