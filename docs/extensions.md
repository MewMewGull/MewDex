# Skills、Memory、Hooks 与 Plugins

在左下角 **设置 → Hub 与执行端设置** 中打开对应选项卡。四类原生能力由 Hub 上固定版本的 Codex 运行时提供，管理员通过原有输入指令和回执管理。使用新版 APP 的同时，需要更新对应 Hub。

## Skills

- **项目 Skills** 复用项目指令与自动化配置。选择项目后点击“管理项目 Skills”，编辑名称、说明和指令正文，保存为新的项目配置版本。
- **Hub 原生 Skills** 列出当前范围的全部技能及启用状态。可以创建自定义 Skill，也可以启用或禁用已有条目。自定义文件保存在 Hub 模型运行时目录下的 `skills/mewdex-编号/SKILL.md`。
- 输入 `/` 或 `$` 浏览并调用。插件提供的技能保留运行时命名空间，例如 `$demo:review`。安装或修改技能后，输入菜单会重新读取目录。

项目选择用于发现对应工作区可用的原生条目。原生启停配置由当前 Hub 的运行时共享，创建的原生 Skill 位于 Hub 用户级目录。

## Memory

**项目记忆** 由用户维护，适合保存项目约定、长期偏好和已核实事实。选择项目并打开“编辑项目记忆”，填写正文、勾选启用，然后保存。它与项目配置共用版本、冲突校验和历史恢复。每个回合固定启动时的快照，停用后后续回合省略该正文。旧配置的内容哈希保持兼容。

**Hub 自动记忆** 使用运行时原生能力。可以分别设置总开关、从新对话生成记忆和在后续对话使用记忆。设置保存在 Hub 自有模型运行时配置中，共享范围为当前 Hub。生成与整理的时机、模型调用和数据保留由固定版运行时处理，项目记忆可独立维护。

## Hooks

支持查看当前工作区的 Hook 事件、命令、来源、超时和信任状态，创建命令型 Hook，并启停可编辑条目。事件包括 `SessionStart`、`UserPromptSubmit`、`PreToolUse`、`PostToolUse`、`Stop` 等运行时已支持的事件。

Hook 在 Hub 的运行时工作目录执行。创建后先查看实际命令和来源，再点击“信任并启用此 Hook”。信任绑定运行时返回的当前内容哈希，内容变化后需要重新核对。策略管理的条目由运行时策略控制。设置通过原生配置批量写入接口更新并校验原版本。

## Plugins

管理兼容当前 Codex 运行时的插件，可以添加 HTTPS 仓库或 Hub 本机绝对路径作为插件来源，查看目录并安装、启用、禁用或卸载条目。来源采用运行时支持的 marketplace 格式，例如 `.agents/plugins/marketplace.json` 和 `.codex-plugin/plugin.json`。

安装前界面显示实际来源，提交时再次核对目录指纹、来源与策略。插件可以提供 Skills、Hooks、MCP 工具和应用。附带应用需要独立授权时会显示待授权应用名称。真实第三方插件的账号授权与兼容性需要按各插件完成验收。

## 回执和生效范围

原生管理使用 `extension.read` 和 `extension.update`，仅管理员可以对 Hub 协调端发起。更新保存到原有持久指令账本，结果不明时保留原编号并提供查询入口。界面核对原回执后继续修改，刷新目录期间保留已有数据显示。

原生设置供新对话读取，部分运行时支持的动态配置也会热更新到已加载会话。项目 Skills 与记忆按项目版本在下一回合固定。运行时的自动记忆生成、真实 Hook 命令执行与第三方应用授权需要在实际部署环境验收。
