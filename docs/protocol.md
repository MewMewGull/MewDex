# 输入端协议 v1（开发基线）

输入端只通过 Hub 的 HTTP / WebSocket 协议操作网络。TypeScript SDK 不依赖 React、Tauri、浏览器存储或本机执行器；手机、桌面和未来网页端可以复用它。其他语言也可以按本协议接入。

## 中央账号与认证协商

`MewDexAccount` 是中央后端的用户账号，与 Hub 的 `ModelAccount`（ChatGPT / API 订阅及额度）分开。MewDex 账号登录后返回 `admin` 管理身份及全设备访问权限，`Identity.accountId` 指向稳定账号；切换输入终端不需要逐台授予项目权限。模型账号认证信息由 Hub 的专用引擎目录管理。

- 匿名 `GET /health` 返回 `ServerInfo={name,protocolVersion,capabilities,authentication}`。`authentication={methods,defaultMethod,accountConfigured}` 决定下一步表单；终端先核对服务与协议，只展示支持的已公告方式。已配置账号的 Hub 默认 `methods=["password","key"]`、`defaultMethod="password"`；尚无账号的既有 Hub 以 `key/pair` 兼容初始化。旧 Hub 缺少此字段时继续支持原密钥及配对方式，不假定支持密码登录。
- 匿名 `POST /v1/login` 接收 `{username,password}`，返回与配对相同的 `{token,identity,protocolVersion}`。账号在中央持久化 bcrypt 哈希，明文密码不进入执行指令账本、模型参数或输入端持久存储。失败不保存连接；登录尝试按来源有界限制。每次登录签发随机令牌，账号编号不变。
- 已认证 `GET /v1/mewdex/account` 返回当前 `MewDexAccount` 或 `null`，公开信息只有编号、用户名、名称和创建时间。管理员 `PUT` 同一路径以 `{username,name,password}` 建立当前账号或修改其用户名及密码；没有匿名注册接口。修改账号保留原输入编号及密钥，旧配对身份可通过已有管理员密钥建立账号。
- 密钥认证继续读取 `/v1/me`，使用相同 MewDex 账号权限；账号密码登录得到的令牌也可显式复制作为密钥。系统凭据库只保存地址与令牌。撤销身份会撤销该身份的现有令牌；账号密码仍可用于重新登录。

Hub 的 `mewdex-accounts` 能力声明账号接口，`central-projects` 声明中央项目名称/分类管理。首次配置本机 Hub 可以一并设置 MewDex 账号；独立 Hub 的 `mewdex account -config <profile>` 从标准输入读取账号 JSON，不将密码放入进程参数。

## 身份与目标

- 输入身份为 `client` 或 `admin`；执行器连接使用单独的 `executor` 身份。
- 一个电脑安装可以同时具有输入和执行能力；手机安装只需要输入身份。角色不由操作系统决定。
- 使用 `GET /v1/me` 读取当前身份；`GET /v1/devices`、`GET /v1/sessions` 的结果已按设备和项目授权过滤。
- 对话通过稳定的 `sessionId` 定位，执行位置由 `deviceId` 和 `projectId` 决定。输入端不直接使用引擎 RPC ID。
- 配对码只使用一次，配对返回长期 MewDex 凭据。长期凭据使用 `Authorization: Bearer ...`，不放进 URL。
- 模型账号独立于 MewDex 配对。模型凭据留在执行设备，输入端仅处理管理员可见的账号状态和官方设备登录码。

公网 Hub 使用 HTTPS；SDK 不允许将凭据发给明文公网地址或重定向目标。`allowPrivateHTTP` 仅用于显式选择的私有开发 IP，回环地址仍可用于本机开发。

## 对话整理

`PATCH /v1/sessions/{id}` 由有权访问该设备和项目的 `client/admin` 修改共享的显示信息，执行器身份不能调用。请求可分别包含 `title`、`pinned`、`archived`；省略的字段保持不变，名称去除首尾空白后须为 1 到 120 个字符。返回更新后的完整输入端会话视图，重复设置相同值不生成新事件。

整理信息由 Hub 单独保存，不调用执行器，执行设备离线时仍可修改。会话列表、启动快照、指令回执、历史与实时 `session.updated` 事件均投影相同的名称和标记；原执行会话、回执和事件记录不改写。变更与 `session.metadata.updated` 事件在同一数据库事务中保存；即使只订阅另一条当前对话，此类列表变更仍会送达。执行器后续上报不会覆盖整理信息。

归档只整理列表，运行中的任务、队列、冻结状态和项目占用按原规则继续。恢复不自动发起模型回合。输入端自行决定日常列表和归档库的展示方式。

## 回复位置与已读

`GET /v1/bootstrap` 的 `conversationUpdates` 返回每条可见对话的最新完整模型文字位置，每项仅包含 `deviceId`、`sessionId`、`sequence`。来源是持久的 `engine.item/completed` 中非空 `agentMessage`；用户输入、增量片段、工具和账号事件不计入。没有回复时返回空数组。位置按当前会话的设备和项目授权过滤，执行设备离线不影响读取。

带 `sessionId` 范围的事件订阅将其他对话的上述事件投影为 `conversation.changed`，负载使用同样的三个字段；保留原事件编号、全局序号和时间，去除模型正文。当前对话仍收到原事件，无范围订阅保持原语义。类型过滤作用于投影之后，检查点与回放沿用原事件序号，不再写一份提示事件。

输入端可将位置与本机保存的已读序号比较。这里不增加已读写入接口，也不跨输入端同步阅读状态；已读不改变会话、队列或执行。首次启用以启动快照的 `cursor` 为旧历史基线，快照读取期间产生的更大序号仍视作新回复。旧 Hub 缺少该字段时暂不建立基线，后续升级不会把所有旧历史误记为新消息。

## 模型目录与推理强度

Hub 协调器以 `model-catalog` 声明模型目录读取能力。`model.list` 指令指定协调器 `deviceId` 及 Hub 项目或已有会话，`models` 可携带分页 `cursor` 和 `limit`，默认每页 30 项，最多 100 项。普通已授权输入端可读取目标项目的模型目录，账号管理向管理员开放。协调器核对项目与会话归属后调用引擎 `model/list`。

完成回执的 `ModelPage` 包含 `models` 及可选 `nextCursor`。模型提供 `id`、实际请求使用的 `model`、显示名称与说明、推荐标记 `isDefault`、建议强度和所支持的强度列表。每个强度保留执行端给出的字符串与说明，不由输入协议固定为某几个枚举值。隐藏项不投影，其他引擎私有字段不进入回执。目录只读回执不显示为需要处理的未确认操作。

声明 `reasoning-policy` 的设备接受 `Policy.reasoningEffort`。省略或空值表示交给执行端决定，非空值按固定引擎的可扩展字符串传递；模型和强度与同一策略版本绑定。下一回合的 `collaborationMode.settings` 携带原模型与任务指令，以及明确的 `reasoning_effort` 值或 `null`，不修改全局配置。旧设备未声明能力时，输入端不提供新的强度设置入口。

目录中的推荐项不是项目当前配置的可靠标识，也不是模型账号的权限确认。现有会话的 `defaultModel` 仍来自原引擎回复；未取得继承模型时，输入端保留执行端决定，不按推荐项推断其强度选项。

## 网络任务

`GET /v1/activity` 返回当前输入身份可访问的活动对话，沿用会话列表的设备和项目授权。每项包含已投影的 `session`、待回复及阻塞请求数、排队/投递中的输入数、结果未知的输入数、失败队列项数和 `needsAttention`。请求正文、问题、答案和排队输入正文不进入这些计数。需要处理的任务靠前，其余按会话更新时间排列。

概览包括执行中、停止中、后台进程、仍待处理的队列和待核实状态；已归档的活动任务继续出现。`needsAttention` 覆盖待回复请求、结果未知或失败的队列项、未核实执行/后台进程，以及冻结中的排队消息。已明确结束的 `executionRecovery.state=retired` 执行继续作为历史保留，不进入活动概览；没有待处理项的旧失败会话也不常驻这里。

选中对话的 WebSocket 流会把其他已授权对话的 `interaction.updated` / `queue.item.updated` 投影为 `activity.changed`，负载只含 `sessionId`，保留原事件编号和序号。精确类型过滤作用于投影后的类型。当前对话仍收到原事件，无选中范围的提醒订阅保持原有投影；原始落盘事件和历史不变。输入端收到提示或网络级会话更新后重新读取概览，定时刷新仅补充状态。查询与导航均不启动或恢复任务。

## 指令与结果

`POST /v1/commands` 接受带客户端唯一 `id` 的指令。相同 ID 的重试必须保持来源和业务内容一致；结果未知的操作不能换一个 ID 自动重发。

`GET /v1/commands/{id}` 只查询回执，不重新执行。`completed` 表示控制指令完成，例如消息已交给引擎或已进入队列；模型回合完成另由事件和会话状态报告。

`GET /v1/pending-commands?deviceId=...&after=...&limit=...` 恢复当前输入身份在该设备上发出的 `accepted/unknown` 指令引用。返回稳定编号、目标、类型与状态，不含原始输入、策略或表单内容；管理员也不会因此取得另一个输入身份的收件箱。仍按当前设备和项目授权过滤。默认每页 20 条，最多 200 条，`after` 来自返回值；分页期间完成旧回执不会导致位置偏移。

共享输入端重启、重连和恢复前台后重新查询这些引用。查询和关闭提示均不发送原指令；关闭仅隐藏本次输入应用的提示，不改变服务端执行状态。恢复出的引用不会清空当前草稿或抢占新选择的对话。列表分页、有界显示；继续发送前需处理当前设备的待确认提示。

只读 `account.read` 与 `file.list` 查询不进入此操作恢复列表，也不参与该列表分页。原查询回执仍保存在指令账本中，可按原编号读取。`file.export`、`account.login`、`account.cancel` 和任务操作继续按原规则保留未确认引用。

| `steer`                     | 运行中的对话           | 追加输入，使用 `expectedTurnId` 防止串回合                                                                               |
| `enqueue`                   | 对话                   | 排队输入；停止后保持冻结                                                                                                 |
| `queue.cancel`              | 对话、队列项           | `requestId` 指定队列项，必须带观察到的 `expectedRevision`                                                                |
| `interrupt`                 | 对话                   | 中断模型回合                                                                                                             |
| `stop`                      | 对话                   | 中断回合并清理引擎登记的后台进程，分别确认状态                                                                           |

| `account.read/login/cancel` | 执行设备               | 仅管理员；登录与取消仅限隔离的引擎目录                                                                                   |
| `account.limits/logout` | 执行设备 | 仅管理员；读取实际额度或按用户操作退出当前模型账号 |

停止会优先取消本对话普通指令的等待，保留被取消写入的未知结果。启动回合前持久化原指令 ID；回执丢失时通过引擎历史中的用户输入标识核对实际回合，能够确认已接收的原始 `start` 回执才恢复为 `completed`。未找到对应历史时继续保持未知，不能仅凭本地没有回合编号就认定已停止。

核实模型回合结束与清理后台进程是两步。`reconcile` 不会清理进程，也不会解冻队列；进程尚未核实时，必须先执行 `stop`。`registered-processes-cleared` 仅说明引擎登记的后台进程已清理，不代替操作系统层面的所有孤立进程确认。

正常回合结束后，`stopStatus=background-running` 表示引擎仍登记着运行中的后台进程，项目目录继续占用、队列等待。执行器只读观察其退出后再继续队列。列表缺失或无效时为 `processes-unchecked`，会话暂停并冻结；服务重启后也不会凭旧状态释放未知任务的工作区。

本机恢复在核对系统重启、配置和 OS 租约后，先保存旧执行身份的私有快照，再解除服务启动限制。启动后的未知会话可公布 `executionRecovery={id,state:"eligible"}`。输入端只能引用这个不透明编号，不能传入系统启动批次或进程证明；操作仍受设备与项目授权约束。快照绑定设备、会话、项目、引擎对话和原始启动指令，新的任务不能继承旧证明；只读核实发现或清除旧回合编号不会失去原执行的恢复资格。

`execution.retire` 不接受新输入、策略或交互回复，也不调用引擎。原模型指令回执、回合编号和队列内容保持；控制操作有独立的持久回执，回复丢失后按原编号查询。`executionRecovery.state="retired"` 的旧会话保持冻结和历史可查，拒绝继续执行、恢复、停止及编辑策略；应显式新建对话继续。重开服务不会重新占用旧项目，迟到模型事件也不会改写已结束的旧历史。备份恢复会撤销未采用的重启资格，已结束执行的审计仍作为只读历史保留。

## 项目文件与回传

设备可选的 `capabilities` 包含 `project-files` 时，支持上述文件指令。它们要求已存在的对话，并沿用当前输入身份的设备与项目授权；不创建模型会话、不调用模型 RPC、不继续或结束原执行。文件读取使用当前本机配置，不将新的文件范围写回旧会话的执行范围。

路径为项目相对路径，也可为同平台且确实位于项目内的绝对路径。执行端拒绝越界、私有目录、链接和特殊文件。`file.list` 每页最多 200 项，`next` 用于后续 `after`，`hasMore` 表示还有项；每项返回名称、项目相对路径、目录标记、大小及修改时间。目录变化可能影响后续页，不宣称目录快照一致性。

`file.export` 最多读取 20 MiB 的普通文件，复制后核对大小与修改时间，再保存不可变附件。返回的 `OutputFile` 包含原指令、对话、设备、项目、源相对路径、附件元数据及时间。该副本代表主动读取时的内容，不自动认定为原模型回合的最终产物。

远端执行器使用自身执行身份调用 `POST /v1/file-exports?commandId=...`，正文为文件字节，`X-Mewdex-Output` 为无填充 URL-safe Base64 编码的 `FileExportRequest={path,attachment}` JSON。Hub 从原指令确定输入来源和目标范围，执行身份必须匹配该设备；输入端不能调用此上传入口。Hub 验证附件的大小与 SHA-256，再原子保存索引与 `file.exported` 事件。相同副本重复登记保持幂等，冲突不覆盖已有副本。

`GET /v1/file-exports?sessionId=...` 返回当前输入身份有权访问的对话中最近 200 份副本，按时间倒序；执行端身份不能调用。附件正文继续使用现有附件接口和范围授权，设备离线不影响读取已有副本。上传或指令回执不可靠时，仅按原指令编号查询或读取副本索引；不能换编号自动重复回传。SDK 对发送后的 HTTP 408、5xx 和网络中断保留结果待确认，明确的其他 4xx 则保留实际拒绝状态。

## 队列

`GET /v1/queue?sessionId=...` 返回全部未结束的队列项及最近 50 条记录，按执行端分配的 `position` 排序。顺序不依赖输入设备的时钟；每个对话最多保留 100 条未结束项。

入队时固定输入、附件引用、策略版本及完整任务指令文本。之后编辑会话策略不会重写这些队列项。`queue.item.updated` 广播带版本的进度；输入和策略不可改写，旧事件不能回滚状态。

执行前先把 `dispatching` 状态与补传事件一起持久化，再调用引擎。失败的输入保留；结果未知或执行器重启后不自动重发，待处理队列保持冻结。回执的 `completed` 只说明已入队，任务进度需看队列项的 `running/completed/failed/unknown` 等状态。

仅 `queued` 或 `failed` 项可以取消；已投递的任务需要停止和核实原回合。取消保留历史，不代表撤回已经发生的执行。多个输入端取消同一项时，旧版本请求会被拒绝。

## 策略与版本

`policy` 包含验证模式、不要测试、追加指令、完成条件、模型和可选基础指令。普通任务策略通过固定引擎支持的逐回合接口发送，避免对已载入会话使用无效的配置续接。

版本由策略和实际任务指令文本共同确定。快照保存当时发送的完整文本；恢复历史版本会使用该文本，不重新套用当前程序模板。两个输入端同时编辑时，旧 `expectedPolicyVersion` 会被拒绝。

`baseInstructions` 替换当前对话的基础指令。关闭替换后继承会话初始快照；新对话没有覆盖时由执行端引擎选择基础指令。修改已经开始的对话时保留其历史，基础指令与任务指令分开处理。有未处理交互或后台进程时，拒绝切换基础指令。

`GET /v1/policies?sessionId=...` 返回授权范围内的版本历史。来源接口只提取配置中的指令字段，不返回整个配置对象、模型凭据或原始错误内容。项目指令只展开配置项目目录内的 UTF-8 内容。

## 交互请求

`interaction.updated` 提供统一的 `Interaction`：稳定请求 ID、对话与回合、类型、说明、命令、问题或表单字段、状态。引擎 RPC ID 留在执行端。

`Session.executionScopeId` 与 `Interaction.executionScopeId` 是可选的范围编号，不包含文件路径或凭据。新执行器据此绑定会话和请求；输入端不能提供编号来选择范围，也不能通过回复扩大本机路径授权。旧客户端可以忽略这两个附加元数据字段。

`GET /v1/interactions?sessionId=...` 查询当前待处理请求。回复使用 `InteractionReply`：`action` 为 `accept`、`decline` 或适用的 `cancel`，另带问题答案或表单值。执行端校验字段和原始请求；权限回复不会超出原请求或隐式变成会话永久授权。

输入端必须遵守 `canAccept`。命令支持单次确认；文件修改通过可选的 `filePatch` 显示与当前工具调用匹配的原生变更预览。额外访问通过可选 `permissions` 显示 `readPaths`、`writePaths` 与 `network`；普通权限请求只在当前回合生效，命令的附加权限只用于本次命令。路径由执行端规范化并与私有目录核对，回复中的表单字段不能增加权限。持续目录授权、根目录、通配符或无法核对的环境、预览不能放行；请求仍可拒绝或停止。

额外权限的接受操作需要管理员输入身份，Hub 在原始回复进入去重账本前核对；普通输入端可以拒绝该请求，并继续回答问题及确认已有范围内的操作。`GET /v1/interactions`、历史事件查询和 WebSocket 流均根据当前身份调整 `canAccept`，保持原事件编号、顺序和数据库记录。没有范围编号的旧执行器不能提供权限、命令或文件的接受操作；普通问题不受此限制。

同一请求只处理一次回复。任务停止、原回合结束、引擎撤销请求或执行器重启后，旧请求不能继续放行操作。未知写入结果不自动重放。请求内容、对话归属及终态都不能通过后续事件重写。

交互回复的回执账本保存响应指纹用于去重，不保留答案正文。回复通过已授权的连接交给执行器；引擎和工具服务自身的历史保留规则独立。

## 事件与附件

`GET /v1/bootstrap` 提供按授权过滤的身份、设备、会话和网络游标。游标先于投影读取，读取过程中的并发事件会在后续流中补齐。输入端连接时无需从网络创建之初重放全部正文。

`GET /v1/session-events?sessionId=...&before=...&limit=...` 按对话读取更早记录：`before=0` 为最近一页，返回事件按显示顺序排列，`before` 用于下一页，`hasMore` 表示还有历史。默认 200 条、最多 1000 条，并限制页面约 4 MiB；单条超大事件仍可单独读取，避免形成无法跨越的历史位置。

同一接口可选择 `after` 方向读取较新一页，`after=0` 从最早记录开始；请求选择一个方向。`EventPage.before/after` 分别为当前页首尾事件序号，`hasMore` 始终表示仍有更早记录，`hasNewer` 表示仍有较新记录，两种读取方向均按时间正序返回事件。SDK 分别提供 `historyPage` 和 `historyAfter`。浏览历史不会恢复模型执行；返回实时视图由输入端明确选择。

`GET /v1/message-search?sessionId=...&q=...&before=...&limit=...` 搜索当前有权访问的对话文字，执行设备离线时仍可使用。搜索覆盖 `message.user` 的文本输入和 `engine.item/completed` 中完整的 `agentMessage.text`；不搜索原始事件 JSON、工具输出、账号数据、交互答案或附件元数据。同一模型消息有多份完成记录时按最新记录检索，不把较旧内容再次作为分页结果。

`q` 去除两端空白后须为 1–200 个 Unicode 字符，按普通文字忽略大小写匹配，不使用 SQL 通配符。结果默认每页 30 条、最多 100 条，按事件序号倒序；后续页使用返回的 `before`，`hasMore` 表示还有匹配结果。每条 `MessageMatch` 包含消息 ID、原事件序号、角色、时间及由 `before/match/after` 三段文字组成的有界片段，客户端直接作为文字显示。定位时用匹配序号加一作为历史页的 `before`，可取得包含原消息的记录；这不发起引擎历史指令。SDK 查询支持 AbortSignal，查询关闭或切换后可以取消读取。

`NetworkSnapshot.capabilities` 可选地声明 Hub 的新增读取能力，目前的 `task-plans` 对应 `GET /v1/task-plan?sessionId=...&before=...`。缺少字段的旧 Hub 不启用新查询；声明不替代当前输入身份、设备和项目授权，执行身份不可调用此输入接口。

任务计划从当前对话及设备的持久 `engine.turn/plan/updated` 事件投影，返回 `TaskPlan` 的回合、事件序号、时间、说明、步骤及同一位置的回合状态，不返回原始引擎 payload 或 threadId。`before=0` 读取最新记录，正数为与历史页相同的独占边界，负数及非整数返回 400；输入端以历史页 `after+1` 读取当时计划。不存在计划或新一轮尚未提供计划时返回 JSON null；最新空计划保留空步骤，不回退到更早计划。步骤状态沿用 `pending/inProgress/completed`，回合结束不推断步骤完成。SDK 的 `taskPlan` 支持 AbortSignal，仅向 Hub 读取，不向执行端发送指令。

事件 WebSocket 可带 `sessionId`：非空时只流式传送该对话正文，空字符串只接收网络状态；其他授权对话的会话状态及指令回执仍可更新。未提供该字段时保留原始完整流，供其他输入端按需使用。过滤后仍发送全局检查点。

同一连接可通过重复的 `kind` 参数选择精确事件类型，最多 16 项，每项 1–128 个 ASCII 字母、数字或 `_./-`。过滤仍须通过当前设备、项目与对话授权，交互事件仍按当前身份投影；过滤掉的事件继续推进检查点。SDK 的 `subscribe.kinds` 同时在本地过滤，因此旧 Hub 忽略新增参数时，输入端仍得到相同语义。提醒使用独立的可选订阅，只请求回合结束和交互更新，不改变当前对话正文流。

共享客户端采用有界事件窗口，旧页面离开后清理缓存；查看更早记录时不混入最新正文，返回最新时重新读取。SDK 的 `EventWindow` 不依赖界面，可复用于其他输入端。重连可用新授权快照及其游标替换离线期间的全量回放；访问范围变更或身份失效会清除旧可见缓存。

- 事件先在执行端持久化，再由 Hub 去重并分配全局序号。输入端按序号补传。
- 浏览器事件连接先通过 `POST /v1/events/ticket` 获取一次性短时票据，再连接 `/v1/events/ws`。SDK 只把该票据放入连接 URL。
- `stream.checkpoint` 仅推进过滤后的游标，不作为用户事件渲染。
- 附件上传绑定执行设备和项目；跨设备或跨项目误用会被拒绝。执行端下载后校验大小和 SHA-256，文件内容不作为网络控制指令执行。
- `GET /v1/attachments/{id}` 返回附件元数据，`GET /v1/attachments/{id}/content` 返回二进制正文，均使用当前身份的设备与项目授权。SDK 提供带取消信号的 `attachment`、`attachmentContent`，请求凭据仍在 Authorization 头中，不生成含凭据的下载地址；预览和系统保存由输入端的平台层负责。
- 执行端重新核对已缓存附件的目标；发送和追加时使用本会话经完整性校验的只读视图路径，输入协议不传执行端原始缓存路径。排队验证不创建模型回合或物化附件。
- 撤销身份会关闭现有事件连接、执行器连接及对应请求出口隧道。

## 当前实施边界

`Policy.collaborationMode` 可选，空值表示直接工作，`plan` 表示先讨论方案；输入中的 `default` 规范化为空值，其他取值被当前执行器拒绝。该字段独立于验证范围 `mode`，参与原策略版本、快照、入队保存和历史恢复。只有 `NetworkSnapshot.capabilities` 与目标 `Device.capabilities` 同时包含 `collaboration-modes` 时，新界面才提供设置；缺少任一声明不采用新模式。方案任务发往没有此能力的旧执行器时，Hub 保存明确失败回执，重复原编号只返回该结果；不会忽略模式后继续执行。停止等控制指令继续使用原协议。

桌面本机管理使用独立的原生 JSON 协议 v1，不属于输入端网络权限。Go 的 `internal/localnode` 类型通过同一个生成器生成 `apps/client/src/localProtocol.ts`，包含 `status/setup/start/stop/connect/projects` 操作。原生宿主固定服务程序、资源和应用数据目录，网页请求不能指定可执行文件或根目录。普通快照不包含执行令牌和模型凭据；显式本机输入配对的结果交给平台凭据库保存。

`input_capabilities` 在手机返回 `localService=false`；手机构建不注册本机服务或目录选择命令。网页开发适配器同样只提供输入能力。设备网络的对话、审批、回执与事件仍走独立 SDK，未来新形态输入端不需要复刻原生桥接。

新的原生输入端可返回 `notifications=true`；旧宿主缺少此字段时，共享界面不调用新通知桥接。提醒默认关闭，用户显式开启后才请求系统权限。偏好、游标及有限去重编号按 Hub 和输入身份隔离保存在本机，不包含模型正文或答案；退出和访问范围重置时清除。重新打开后的补齐只读取事件，不重发模型输入。当前实现为应用在线时的系统提醒与恢复后的补齐，不包含应用被系统挂起或关闭时的远程推送服务。

`notificationActions=true` 表示支持原生点击暂存：Rust 在应用初始化时登记回调，只保留最近一个有界定位提示；输入端通过 `notification_take_action` 取走一次，启动、实时唤醒和恢复前台使用同一路径。提示仅含动作、通知编号、Hub/输入身份范围、设备和对话编号，不授予网络权限；实际打开前仍重新读取当前授权对话。旧宿主缺少此字段时沿用其既有事件监听方式。手机的此项接口只服务输入导航，不提供本机执行能力。

触控输入界面的回车用于换行，Ctrl/Command + Enter 可显式发送；普通桌面保留 Enter 发送、Shift + Enter 换行。键盘可见区域和消息区尺寸由共享输入 UI 处理，不进入网络协议或执行器。界面会保留原指令编号；关闭输入应用或恢复前台不会重新提交模型消息。

Hub 运行共享模型引擎时，快照声明 `hub-projects` 和 `hub-model-account`。`Project.directories` 保存跨机器目录引用，中央项目的 `path` 为空，`revision` 用于并发更新校验。`GET /v1/projects` 返回中央项目，管理员通过 `PUT /v1/projects/{id}` 提交名称、分类、目录组和 `expectedRevision`。

执行节点声明 `hub-execution`。Hub 通过已配对控制连接发送 `terminal.exec`、`terminal.wait`、`terminal.stop`、`terminal.stopOwner`，输入端的 HTTP 指令入口拒绝直接提交这些操作。回合的 `ownerId`、工具调用生成的稳定指令编号和本机任务编号共同限定执行归属。重连查询原编号，停止回合会在节点留下持久拒绝标记。

`FileRequest.directory` 选择 Hub 项目目录组中的目录，下发的 `terminal.file.list` 和 `terminal.file.export` 由节点完成。文件回传使用原输入请求的授权和快照编号，上传节点需匹配 Hub 解析的执行目标。`OutputFile.directory` 记录快照的来源目录。

本文件记录当前开发协议，不代表产品已验收。停止和重启后的完整进程确认、手机后台恢复及生产安装分发仍在实施。服务不能把失联显示成已停止；界面也不能用控制指令回执替代完整回合完成状态。

## 原生本机管理接口

独立分发后的输入 APP 声明 `localService=false`，通过网络 SDK 管理 Hub。桌面 APP 的 `channel_connection` 接口启动专用消息连接器，连接配置通过原生管道交付。

`GET /v1/input-bridges` 列出当前管理员身份下的在线 APP。APP 以该管理员凭据连接 `/v1/input-bridges/ws?id=...&name=...`，Hub 将 `/v1/messaging` 请求转发给选定连接。可选 `bridgeId` 显式指定 APP，多个连接时必须选择。该连接用于渠道管理，渠道提交继续通过带项目范围的普通 `client` 身份使用 `/v1/commands`。平台凭据和收发回执由 APP 保存。

执行端的独立网页控制面板通过带面板密钥的 `/api/device` 调用现有本机管理层。执行节点仍通过 `/v1/node/ws` 与 Hub 建立主动连接。

`apps/client/src/localProtocol.ts` 由 Go 管理类型生成，独立于网络输入 SDK。电脑原生宿主可以调用本机管理程序；手机和网页不暴露本机执行、配置或数据恢复命令。

长期操作采用 `job.start`、`job.status`、`job.cancel`。支持加密备份、恢复准备、升级准备和显式采用已审阅方案。创建前生成 32 位小写十六进制编号；同一编号不会启动第二个工作进程。查询可以恢复原编号的结果，未被接受的编号返回空任务；未知结果不重新执行。`restore.prepare`、`upgrade.prepare` 的方案编号与创建任务编号一致；相应 apply 操作使用新的任务编号并指向原方案。

后台任务的记录与租约由 Go 层管理，原生窗口只轮询实际进度。口令不作为命令行参数或持久请求保存；工作进程通过标准输入接收一次性请求。`restore.status` 只读取方案和当前采用状态，不能隐式切换或启动服务。恢复后重新加入网络需要新的授权。

`upgrade.prepare/apply/status` 使用 `UpgradeRequest.id` 和 `UpgradeInfo`，不接受客户端提供程序或数据路径。准备迁移当前安装的新副本，采用时保留当前网络授权及模型目录；结果未知时只观察原编号。详细范围见 [数据生命周期](data-lifecycle.md)。

本机快照可选 `operations` 声明当前管理程序支持的操作。新输入界面据此展示升级入口；旧程序没有此字段时，不展示新增操作。能力声明不替代设备、停止状态和计划指纹校验。

`repair.executor` 在安装停止后核对或重新配对本机执行器。空配对码只检查现有身份或继续已保存的配对结果。有效身份不消耗新邀请，只有明确 401 或缺失凭据允许创建替代身份；旧凭据和未知尝试保留。一次尝试的未知结果不重发同一邀请，显式不同邀请开始另一次尝试。原生快照的 `pairingRequired` 同时覆盖缺失凭据和与当前文件指纹匹配的已拒绝授权；普通状态查询不主动访问远端 Hub。

`startup.status` 读取本安装的系统启动登记与配置匹配状态；`startup.apply` 接收 `StartupRequest.enabled`，启用或移除未来启动入口，不隐式停止当前服务。返回的 `StartupInfo` 包含系统作用范围、请求意图、实际登记、配置与入口匹配及待核对状态，不含执行身份或模型凭据。结果未知后只查询状态；显式重试先核对已接受结果，不重新建立另一登记。

`service.port` 接收 `ListenerRequest.port`（1–65535）和 `expectedDeviceId`，仅在 Hub 停止时保存用户指定的监听端口，保持监听主机与设备身份，并同步已有自启动登记。保存不隐式启动服务；未识别到 Hub 的端口占用通过 `start` 返回包含端口号的错误，不自动换端口或采用其他 Hub 的管理配置。

`hub.discover` 只读取当前监听端口的公开 Hub 信息，结果通过 `Result.existingHub={baseUrl,protocolVersion}` 返回；不返回凭据、不修改当前配置或进程归属。`start` 发现端口上已经运行 MewDex Hub 时也返回该字段，桌面端转入该地址的标准登录流程；其他服务占用仍返回端口冲突。登录页会再次核对协议和认证方式，识别到 Hub 本身不构成登录。

`proxy.ssh.config` 要求 `expectedDeviceId` 匹配当前本机 Hub，读取当前用户的 `.ssh/config`，通过 `Result.sshConfig` 返回具体 Host 别名及其服务器、端口、用户、私钥路径、主机密钥文件路径和可导入状态。读取不修改设置或原 SSH 文件，不读取私钥内容，也不建立 SSH 连接。输入端选定主机后仍通过 `proxy.apply` 保存可编辑的连接参数；公网地址、代理开关和远端转发设置保留原值。

系统入口执行固定程序的 `managed -root ... -owner ...` 前台模式。安装租约覆盖服务与引擎清理全过程；被禁用、被恢复或已变化的配置不自动启动。所有权标识只用于避免误动其他登记，不是网络授权凭据。手机与网页输入端不暴露此本机接口。

`project.location` 是只读本机操作，要求 `expectedDeviceId` 匹配当前配置，并用 `projectId` 选择已配置项目。结果的可选 `project` 返回规范目录；请求不接受自选路径。桌面原生宿主可据此定位本机项目目录，手机和网页只使用网络文件接口。
