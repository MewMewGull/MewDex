## 已落地的开发实现

- Go 协议、SQLite 持久化、Hub API、一次性配对与角色身份。
- Executor 独立于界面与 Hub，Codex stdio RPC、流式事件、会话创建与续接、追加、排队和中断。
- 模型中断与后台进程清理分开确认，未知停止状态保留；停止冻结排队消息。
- 事件先落盘后确认，重连重传；Hub 原子写入事件与查询视图，重复旧事件不回滚会话状态。
- 独立执行端的 WebSocket 连接、心跳和重连；命令按 ID 与来源去重，不自动重放结果未知的命令。
- HTTPS CONNECT 请求出口、目标白名单、每设备独立授权及隧道计数；撤销设备会关闭其现有隧道。
- 附件上传、哈希校验和目标端传输接口；图片映射到 Codex 本地图片输入。两台真实服务器已验证传输后的文件哈希和跨执行器下载隔离；Windows 真实模型已读取文件、图片，并在数据迁移后从新路径索引读取历史附件。
- 提示词策略、来源查看、预览、保存及历史版本恢复；快照包含实际指令文本，旧版本编辑会被拒绝。执行范围已接入会话生命周期，三平台实际原生工具检查通过。
- TypeScript SDK 不依赖 React/Tauri，协议类型由 Go 生成。
- React 共享输入端、设备与会话选择、流式消息、附件、策略设置、终端及差异面板。
- Tauri 桌面/移动外壳源代码；Windows / Mac 系统凭据库适配已编译，Windows 临时凭据写入、读回、清除探测通过。Android arm64 与 iOS 模拟器目标的 Rust 编译检查通过；iOS 模拟器已实际配对、保存凭据、向 Windows 发送文本和恢复历史，Android 应用尚未启动。浏览器开发适配器仅保存本次浏览器会话凭据。
- 输入端访问范围可按设备、项目设置；一次性配对、身份修改与即时撤销已接管理界面。
- 服务使用 OS 文件锁和带实例标识的本地控制通道；更新前通过 `stop` 正常退出，避免按 PID 杀错进程。
- 模型账号状态只返回类型、套餐和是否登录；隔离的 engine.home 支持官方设备码登录与取消，使用已有全局账号的执行器只读。
- 统一交互协议覆盖命令、文件、回合权限、提问及基础 MCP 表单/网页请求。界面和独立 SDK 使用相同请求对象；引擎 RPC ID 留在执行端。
- 同一引擎请求只采纳一次回复；任务停止后拒绝放行旧请求，执行器重启后旧请求过期。未知回复结果不自动重发。
- 引擎通知与 RPC 返回分开投递；消费端暂时阻塞时，通知不会堵住控制指令返回。队列有上限，溢出断连并保留未知执行状态，不丢弃事件后继续执行。
- 任务队列保留原始输入、入队策略和执行状态；投递状态与事件原子持久化，失败不删除输入，重启不自动执行。共享输入端可查询并按版本取消待执行项。
- 停止优先取消普通 RPC 等待；通过原指令标识核实实际回合，修复已被引擎接收的未知启动回执。核实状态、后台进程清理和恢复队列分别处理，无法取得证据时保留未知。
- 网络快照、按对话分页、有界事件窗口及选中对话的事件流；共享输入端重连刷新访问范围，撤销后清除旧可见缓存。界面运行与手机后台行为仍需实际检查。
- 服务启动将缺少完成证据的旧 `accepted` 回执转为 `unknown`；仅从可核对的持久证据修复，避免重启后永久等待或重复执行。设备 HTTP/WS 连接拒绝重定向。
- 输入端恢复前台时刷新网络快照、当前历史与交互，不重发输入；未知回执可同时保留多项。发送增加同步重复提交保护，终端组件按需载入。
- Hub 内置模型 WebSocket 转发与执行端临时回环代理；子进程仅持有本地临时代理密码，设备令牌留在服务中。
- 输入应用可按自己的身份与目标设备分页恢复待确认指令引用，不取回原输入或表单；重连后刷新，同一页面未确认前限制继续发送。异步创建和发送按选择版本处理，切换对话后不会清空另一份草稿；正文保留原始空白。
- 本机设备管理由独立 Go 模块负责，通过固定程序的原生桥接接入桌面。首次配置、启动、停止、本机输入配对及项目选择已有界面入口；手机和网页仍只用网络 SDK。服务与完整引擎资源按哈希存入应用目录，未完成配置保留已配对的执行身份。
- 项目目录绑定持久化；同一执行器按真实目录及父子关系排除并行任务。回合完成后仍有引擎登记的后台进程时，保持目录占用和队列等待，读取失败则冻结；未知任务不会因迟到事件释放工作区。
- 输入端提醒：共享分类与有界去重账本、独立事件订阅、显式系统权限、当前对话前台抑制和恢复补齐；点击先重新确认对话访问权限。桌面和手机接入原生通知，网页使用浏览器通知；实际 OS 投递与点击仍待原生运行检查。当前不含后台远程推送服务。

## 引擎子进程生命周期

后台设备服务持有引擎的进程管理资源，图形输入窗口不持有它们；关闭工作台仍保留服务。`internal/childprocess` 与模型 RPC 独立，版本探测和长期 stdio 引擎复用同一启动、等待和清理边界。

Windows 使用未命名 Job，启用 `KILL_ON_JOB_CLOSE`。新进程先暂停，加入 Job 后才恢复主线程；绑定失败则结束本次创建的进程。结束时只操作自己持有的 Job，不按进程名搜索或结束其他程序。其继承与嵌套语义依据 [Microsoft Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) 和 [AssignProcessToJobObject](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-assignprocesstojobobject)。

Mac/Linux 为引擎创建单独进程组。正常关闭、输出断开或主进程退出时清理继承该组的后代；这还不证明任意脱离进程组的程序已受完整隔离。Linux 的 OS 管理服务已通过无模型强制退出检查，包括新会话的模拟进程；Mac 同场景仍留下模拟进程，必须继续实现。实际证据与限制见 [执行进程生命周期](process-lifecycle.md)。单对话的停止仍通过引擎登记的回合和后台进程处理，不以结束共享引擎替代单任务停止。

stdout 由独立的 `os.Pipe` 提供，主进程等待与流式读取分开；Go 自带 `StdoutPipe` 的等待关闭语义见 [os/exec](https://pkg.go.dev/os/exec#Cmd.StdoutPipe)。本机检查通过受控子进程持有的 OS 文件租约核对退出，不以单个 PID 消失推断整个进程范围已经清理。
