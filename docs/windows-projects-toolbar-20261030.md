# 项目与输入区修订（2026-10-30）

根据用户第二轮截图，调整三处实际使用问题。

## 模型设置与输入区

新对话选择模型和思考强度只修改这条输入的设置，不创建会话、不发送消息，也不再展示“下一回合生效”。模型与强度在工具栏直接显示；正在执行的对话修改设置时，悬停说明适用范围。

输入区底部保持一行：附件、项目、访问权限、任务策略用图标；右侧保留上下文图标、模型和强度、发送。点击图标展开对应设置，完整任务策略从菜单进入。常规设备路径、发送快捷键不再占一行，仍可通过悬停和辅助说明读取。

## 创建与整理项目

左栏“创建项目”只要求名称、目标机器、源文件夹和可选分类。本机使用系统文件夹选择器；其他机器通过目标节点的目录浏览器选择，也可直接输入路径。`~/` 按目标机器的用户目录解析。

左栏默认展示全部可见机器上的项目，按分类组织，机器名称和连接状态与项目同时展示。项目与分类均可折叠，项目的更多按钮编辑名称和分类，右键菜单可直接移动到已有分类或填写新分类。对话继续属于原机器和项目，不因展示名称变化而改变执行位置。

已登记的同一文件夹若收到不同名称或分类的“创建”请求，会明确提示从项目菜单整理，避免悄悄忽略用户填写或改写共享项目。

## 旧本机服务更新

上一版窗口与后台独立运行，旧后台没有工作区管理能力，导致新窗口只显示更新提示。现在创建或保存本机项目时，可通过原生桥调用 `service.update` 应用当前安装包的后台组件：

1. 核对本机身份和当前实例，确认本机执行及 Hub 上仍在运行的任务已完成。
2. 将新组件放入安装目录，停止原实例；如原来启用了自动启动，更新它引用的组件。
3. 启动并等待服务就绪，用原连接创建或保存工作区。

配置、模型账号位置、设备身份、已有工作区和历史不迁移。存在进行中或未确认的本机执行时，返回具体任务名称并保留表单；不结束用户任务来完成更新。

此入口只管理桌面本机。Mac 或服务器上的旧版执行器仍需升级到支持工作区管理的版本；本轮未替换这些正在运行的远端服务，不把已建立传输连接等同于软件能力已经更新。
